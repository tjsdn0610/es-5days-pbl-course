# MD 작성 가이드 — Day 1

이 문서는 학생이 **개인 GitHub 저장소**에 Day 1 동안 작성할 Markdown 파일과 작성 예시를 안내합니다.

- 강사 배포 저장소의 파일은 수정하거나 제출하지 않습니다.
- 예시는 `도서관 도서 검색` 주제입니다. 학생은 예시의 주제·사용자·문서·질문을 자신의 PBL 주제로 바꿉니다.
- Day 1에는 아직 mapping, 대량 데이터, Dashboard 결과를 작성하지 않습니다. 해당 내용은 Day 2~5에 실제로 수행한 뒤 추가합니다.
- 실제 비밀번호, `.env` 값, 개인정보는 어떤 파일에도 기록하거나 commit하지 않습니다.

## 1. `README.md`

Day 1의 README는 프로젝트의 **첫 설계 기록**입니다. 학생이 무엇을 검색하려는지, 검색 결과 한 건이 무엇인지, 어떤 질문을 검증할지를 짧고 구체적으로 씁니다.

### 작성 기준

- 사용자 1명을 정합니다.
- 검색 결과 한 건의 단위를 1개로 정합니다. 예: 도서 1권, 숙소 1곳, 영화 1편.
- 질문 1개는 자유 검색, 질문 2개는 조건 검색, 질문 3개는 Dashboard로 요약할 질문으로 작성합니다.
- 아직 확인하지 않은 Docker·Kibana 상태에는 `확인 전`이라고 씁니다.

### 샘플

```md
# 도서관 도서 검색 PBL

## 1. 프로젝트 소개

- 문제와 사용자:
  과제나 독서를 위해 필요한 책을 찾는 대학생이
  제목과 조건으로 도서를 찾는다.

- ES로 검색할 문서 1건:
  도서 1권

- 이 주제를 선택한 이유:
  제목 검색뿐 아니라 대출 가능 여부와 카테고리 조건을
  함께 적용하는 검색을 만들고 싶다.

## 2. 검색 질문 초안

| 번호 | 사용자 질문 | 예상 조건 또는 결과 |
|---:|---|---|
| 1 | "파이썬" 관련 도서를 찾고 싶다. | 제목 또는 설명에 파이썬이 포함된 도서 |
| 2 | 대출 가능한 과학 도서만 보고 싶다. | 카테고리=과학, 상태=대출 가능 |
| 3 | 어떤 카테고리의 도서가 많은지 알고 싶다. | 카테고리별 도서 수 요약 |

## 3. 결과에 보여 줄 값과 후보 조건

- 검색 결과 한 줄에 보여 줄 값: 제목, 카테고리, 대출 상태, 발행 연도
- filter 후보: 카테고리, 대출 상태
- 정렬 후보: 발행 연도, 대출 수

## 4. Day 1 환경 확인

- Docker Desktop: 확인 전
- Kibana 접속: 확인 전
- Console 첫 요청: 확인 전
```

| 2 | 대출 가능한 과학 도서만 보고 싶다. | 카테고리=과학, 상태=대출 가능 |

## 2. `docs/pbl-start-card.md`

README의 핵심 설계를 한 장으로 정리하는 카드입니다. Day 2의 데이터 모델과 Day 4의 Dashboard 계획의 출발점이 됩니다.

### 작성 기준

- 질문 1은 키워드 입력으로 후보를 찾는 질문입니다.
- 질문 2는 category·상태·가격·날짜 같은 정확 조건이나 범위로 결과를 좁히는 질문입니다.
- 질문 3은 `카테고리별 수`, `월별 추이`처럼 결과 집합을 요약하는 Dashboard 질문입니다.

### 샘플

```md
# PBL 시작 카드

- 프로젝트 주제: 도서관 도서 검색
- 사용자는 누구인가: 과제나 독서를 위해 책을 찾는 대학생
- ES로 찾게 할 문서 1건은 무엇인가: 도서 1권
- 사용자가 입력할 검색 질문 1: "파이썬"을 제목이나 설명에서 검색한다.
- 사용자가 입력할 검색 질문 2: 대출 가능한 과학 도서 중 평점 4.0 이상인 책을 찾는다.
- 사용자가 입력할 검색 질문 3: 카테고리별 도서 수와 평균 대출 수를 확인한다.
- 필터에 사용할 분류 field 후보: 카테고리, 대출 상태
- 정렬에 사용할 숫자·날짜 field 후보: 발행 연도, 대출 수
- Dashboard에서 답할 질문 1: 어느 카테고리의 대출 가능 도서가 부족한가?

## 범위 확인

- ES index, 검색 요청, 분석·Dashboard를 완성한다.
- 실제 이용자 정보와 실제 대출 기록은 사용하지 않는다.
- Day 2에 최소 1,000건의 합성 데이터를 만들 계획이다.
```

## 3. `docs/data-model.md`

Day 1에는 **대표 문서 1건**과 field 역할의 초안만 작성합니다. ES type과 mapping은 Day 2에 실제 설계·검증한 뒤 확정합니다.

### 작성 기준

- 검색 결과 한 줄에 표시할 값을 먼저 정합니다.
- 대표 문서에는 실제 개인정보를 넣지 않습니다.
- field마다 검색·filter·정렬·집계 중 어느 역할을 할지 적습니다.
- Day 1의 type은 `후보`입니다. Day 2에 바뀔 수 있습니다.

### 샘플

~~~~md
# 데이터 모델 초안

## 1. 문서 단위

- 검색 결과 한 건은 무엇인가: 도서 1권
- 이 문서 한 건이 사용자에게 보여 주는 정보:
  제목, 카테고리, 대출 상태, 발행 연도, 평점

## 2. 대표 문서 예시

```json
{
  "book_id": "BOOK-00001",
  "title": "혼자 공부하는 파이썬",
  "description": "파이썬 기초 문법과 실습을 다루는 입문서",
  "category": "과학",
  "status": "대출 가능",
  "published_year": 2024,
  "loan_count": 125,
  "rating": 4.6
}
```

## 3. 핵심 field와 역할

| field | 예시 값 | 검색에서 맡는 역할 | ES type 후보 | 선택 이유 |
|---|---|---|---|---|
| `title` | 혼자 공부하는 파이썬 | 전문 검색·표시 | `text` | 사용자가 제목 단어를 입력한다. |
| `category` | 과학 | 정확 조건·집계 | `keyword` | 카테고리를 정확하게 골라야 한다. |
| `status` | 대출 가능 | 정확 조건·집계 | `keyword` | 대출 가능 도서만 남긴다. |
| `published_year` | 2024 | 범위·정렬 | `integer` | 최근 발행 도서를 찾는다. |
| `loan_count` | 125 | 정렬·집계 | `integer` | 인기 도서를 대출 수로 비교한다. |

## 4. 검색 질문과 field 연결

| 검색 질문 | 사용할 field | 확인할 역할 |
|---|---|---|
| 파이썬 도서 검색 | `title`, `description` | 전문 검색 |
| 대출 가능한 과학 도서 | `category`, `status`, `rating` | 정확 조건·범위 |
| 인기 도서 확인 | `loan_count`, `published_year` | 정렬 |

## 5. 제외할 데이터

- 수집하거나 저장하지 않을 개인정보: 이용자 이름, 학번, 연락처, 실제 대출 이력
- 제외 이유: 이 PBL은 도서 자체를 검색하는 과제이며 개인정보가 필요하지 않다.
~~~~

## 4. `docs/quality-test.md`

Day 1에는 아직 query를 실행하지 않습니다. 대신 나중에 통과 여부를 판단할 **기대 결과·제외 결과·0건 조건**을 미리 정합니다.

### 샘플

```md
# 검색 품질 점검표

| 번호 | 검색 질문 | 기대 결과 | 제외 결과 | 0건 조건 |
|---:|---|---|---|---|
| 1 | 파이썬 도서 검색 | 제목 또는 설명에 파이썬이 있는 도서 | 관련 없는 역사 도서 | 존재하지 않는 제목 검색 |
| 2 | 대출 가능한 과학 도서 | 과학·대출 가능·평점 4.0 이상 도서 | 대출 중 도서 | 평점 6.0 이상 |
| 3 | 인기 도서 확인 | 대출 수가 높은 도서가 위에 표시 | 대출 수가 낮은 도서가 상위 표시 | 발행 연도 2100년 이후 |

> 실제 요청과 결과는 Day 3에 작성한다.
```

```md
# Dashboard 계획

## 1. Dashboard 사용자와 목적
```

## 6. `evidence/day-01-environment.md`

이 파일은 Docker와 Kibana를 실제로 확인한 학생만 작성합니다. 실행에 실패한 학생은 오류 문구와 시도한 조치를 기록하고, 비밀번호는 쓰지 않습니다.

### 접속 성공 샘플

```md
# Day 1 환경 확인 기록

- 확인 일시: 2026-09-01 16:20
- Docker 상태: Elasticsearch 3개 node와 Kibana 컨테이너가 실행 중
- Kibana 접속: `http://localhost:5601` 접속 성공
- `GET /` 확인: version number가 `9.5.0`
- `GET /_cluster/health` 확인: status가 `green`
- `GET /_cat/nodes?v` 확인: node가 3개 표시됨

> 비밀번호, `.env` 실제 값, 토큰은 기록하지 않는다.
```

### 실행 실패 샘플

```md
# Day 1 환경 확인 기록

- 확인 일시: 2026-09-01 16:20
- Docker 상태: 실행 실패
- 화면의 오류 문구: Docker Desktop에서 WSL 관련 오류가 표시됨
- 시도한 조치: `wsl --shutdown` 실행 후 Docker Desktop 재시작
- 다음 조치: `wsl --status` 출력과 오류 화면을 강사에게 제출

> 비밀번호, `.env` 실제 값, 토큰은 기록하지 않는다.
```
