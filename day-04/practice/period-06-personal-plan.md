- 필수 권장 시간: 42분

- 제출 상태 확인: 5분

- 함께 작성: `../evidence/day-04/dashboard-plan.md`

## (개인·필수) 문제 1 — 사용자와 판단 하나로 좁히기

Dashboard를 사용할 사람 한 명과 그 사람이 내릴 판단 하나를 정하세요.

### 답안

- 내 주제: KBO 프로야구 선수 시즌 성적 데이터 (`kbo-players`)
- 한 문서의 의미: 선수 1명의 특정 시즌 성적 기록 1건
- 사용자 한 명: OO구단 전력분석 담당자
- 사용자가 반복해서 하는 일: 포지션별로 보강이 필요한지 주기적으로 선수 성적 데이터를 훑는다
- Dashboard를 보고 결정할 것: 어느 포지션에 일정 성적(예: 타율 0.28 이상) 이상의 현역 선수가 부족한가
- 결정 뒤 수행할 행동: 부족한 포지션의 트레이드/영입 후보 리스트업을 스카우트팀에 요청
- 사용자에게 필요 없는 정보: 은퇴 선수의 세부 기록, 개별 경기 로그, 투수 세부 지표(타자 보강 판단 시)

`모든 사용자`, `전체 현황`, `데이터를 본다`처럼 넓은 표현은 한 사람과 한 행동으로 좁힙니다.

## (개인·필수) 문제 2 — 서로 중복되지 않는 질문 4개

다음 역할을 하나씩 사용해 질문 4개를 작성하세요.

1. 전체 규모
2. 그룹 비교
3. 수치 분포 또는 정확한 값 비교
4. 상태 비율 또는 시간 변화

| 번호 | 분석 질문 | 질문의 답으로 내릴 판단 | 다른 질문과 겹치지 않는 이유 |
|---|---|---|---|
| Q1 | 현역 선수는 총 몇 명인가? | 데이터 커버리지가 판단에 충분한지 | 그룹·분포·비율이 아닌 단일 총계 |
| Q2 | 팀별 선수 수는 어떻게 다른가? | 특정 팀 데이터가 편중됐는지 | 팀(범주)축으로만 나눔 — 포지션·수치·시간 안 씀 |
| Q3 | 포지션별 평균 타율(AVG)과 선수 수는? | 어느 포지션의 타격이 상대적으로 약한지 | 정확한 수치(평균)를 표로 비교, 규모/비율 아님 |
| Q4 | 데뷔·활동 시즌(SEASON) 구간별 선수 수 분포는? | 세대 교체(젊은 선수 유입) 상황 | 유일하게 시간(연도)축 분포 — 나머지는 시간축 없음 |

## (개인·필수) 문제 3 — 질문별 field 존재 여부 점검

각 질문에 필요한 field가 실제 mapping과 문서에 있는지 확인하세요.

| 질문 | 필요한 field | mapping type | 실제 존재 | 값이 충분히 분포 | 가능/가공 필요/추가 필요 |
|---|---|---|---|---|---|
| Q1 | STATUS | keyword | O | 현역 3,498 / 은퇴 1,502 | 가능 |
| Q2 | TEAM_NM, STATUS | keyword | O | 10팀 473~518건 균등 | 가능 |
| Q3 | POSITION, AVG | keyword / float | O | 4포지션 균등, AVG 0.18~0.38 | 가능 |
| Q4 | SEASON | integer | O | 1982~2025, 5년 구간별 330~595건 | 가능 |

- 현재 데이터로 바로 만들 수 있는 질문 수: 4
- 선택한 A/B/C 경로: A (개인 데이터로 제작)
- 선택 이유: 4개 질문 유형(전체 규모·그룹 비교·정확한 값·시간 분포)이 모두 기존 `kbo-players` field로 답이 되고 값 분포도 충분하다.

## (개인·필수) 문제 4 — 부족한 데이터 생성 규칙 설계

현재 답할 수 없는 질문 하나를 선택하고 필요한 데이터를 구체화하세요.

- 답할 수 없는 질문: 시즌 중 월별 타격 페이스는 어떻게 변하는가?
- 부족한 field: `GAME_DATE` (경기 일자)
- mapping type: date
- 예시값 3개: `2025-04-05`, `2025-06-20`, `2025-09-11`
- 범주라면 고유값 수: 해당 없음 (date)
- 수치라면 최소·최대·대표 구간: 해당 없음
- 상태라면 예상 비율: 해당 없음
- 날짜라면 기간과 단위: 정규시즌 3월~10월, 월 또는 주 단위 집계
- 다른 field와 필요한 관계: 지금의 "선수-시즌" 문서를 "선수-경기" 단위로 분해. `P_ID` + `GAME_DATE` + 그 경기의 타수·안타·홈런을 갖고, 경기 기록 합계가 원본 시즌 `AVG`·`HR`에 수렴해야 함.
- 한 문서를 생성하는 규칙: 선수마다 시즌당 100~144경기, 각 경기에 타수 3~5·안타 0~4를 시즌 최종 타율에 맞게 분배(월별로 약간의 랜덤 변동 부여)
- 필요한 문서 수와 이유: 현역 타자 약 3,000명 × 시즌 100경기 ≈ 30만 건. 월별 추이 곡선이 들쭉날쭉하지 않고 의미 있게 보이려면 표본이 충분해야 함
- seed 고정 여부: 예 (재현성 확보)
- 생성 후 검증 방법: 경기 단위 안타 합 / 타수 합으로 계산한 타율이 원본 시즌 `AVG`와 ±0.005 이내인지 확인

“랜덤으로 많이 만든다”는 규칙이 아닙니다. Dashboard에서 비교·분포·필터 결과가 나타나도록 값의 범위와 관계를 적습니다.

## (선택 도전) 문제 5 — 청사진 상호 검토

옆 학생과 `dashboard-plan.md`만 교환하고 말없이 다음 항목을 표시하세요.

- [ ] 모든 질문에 필요한 field가 적혀 있다.
- [ ] 데이터에 없는 질문은 보강 규칙이 있다.
- [ ] 차트와 확인 기준이 연결된다.

- 상대가 남긴 보완 의견: Q3와 Q4가 둘 다 "포지션·성적" 느낌이라 역할이 겹쳐 보인다는 지적
